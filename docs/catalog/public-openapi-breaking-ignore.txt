# Declared breaking changes for docs/catalog/public-openapi.yaml.

# oasdiff --err-ignore matches by SUBSTRING: an entry suppresses a breaking
# change when the entry line CONTAINS oasdiff's own error text verbatim
# ("in API <METHOD> <path> <description>"), so prose may surround an entry but
# never interrupt it. Lines that match nothing — this header included — are
# inert. Removing an entry re-arms the gate for that change.
#
# The wave 190 (error envelope: application/problem+json → application/json) and
# wave 194 (removal of the name{ja,zh,other} buckets) declarations that used to
# fill this file are gone. Both waves are merged into the base this gate diffs
# against, so every one of their entries had already gone inert — re-checked with
# the pinned oasdiff 1.21.0, which reports neither an error-envelope change nor a
# bucket removal against the base. Their rationale survives in git history.
#
# Wave 209 (2026-08-18) makes the public face's name projection TERMINAL. Before
# this wave a name reached the wire under three different shapes depending on
# which projection it came out of: `display_name` on the detail faces, `name` on
# the roster/credit/relation/search projections, and a bare `[]string` for
# aliases. A consumer therefore needed one render path per projection, and the
# three-step fallback each of them documented separately.
#
# After it there is exactly ONE name primitive everywhere an entity name is
# projected — detail, list, roster, voices, credits, siblings, label relations,
# via_label and search hits alike: `display_name` + `latin` (when known) +
# `localized{}`, rendered as `localized[locale] ?? display_name ?? latin`. The
# two breaking families below are what that unification costs.
#
# (1) `name` → `display_name` on the projections that still used the short key:
# search hits, roster characters and their voices, credit items, label relations
# and via_label. This is a RENAME, not a removal: the same string ships in the
# same object under the new key, in the same response, in this same change. No
# value became unreachable — a consumer reading `.name` reads `.display_name`.
#
# (2) `aliases[]` changed item type from `string` to
# `{value, lang, kind, machine}` on the character / credit-name / label detail
# faces, and therefore on lookup and lookup/batch, which embed those records.
# The flat list could not answer the two questions consumers actually had of it:
# what language is this spelling in, and did a human/upstream write it or did a
# translator model. Both are now on the row, so an alias list can be filtered by
# locale and machine text can be badged instead of passing as source text. The
# old string is `value` verbatim; the list is deduplicated by value+lang and, as
# before, excludes the display name itself.
#
# Not breaking, listed so the reviewer knows the whole wave and not just its
# sharp edge: `localized{}` was added to every projection that lacked it, the
# five per-entity intro DTOs collapsed into one `PublicIntro
# {lang,intro,source,machine}`, and PublicWorkBrief (plus works-type search hits)
# gained the `names` block that the works list already published. All additive.
#
# One semantic change rides along and is deliberately NOT gated, because it
# widens rather than narrows: a machine-provenance alias may now FILL a
# `localized{}` locale slot that has no source-provenance name, carrying
# `machine: true`. A source row still always wins the slot — the machine row can
# only occupy an otherwise empty one. The pre-wave rule (machine rows excluded
# from localized{} outright) was what left zh readers staring at a Japanese
# display name while a usable Chinese rendering sat in the alias table. Consumers
# that must not show machine text filter on the flag; consumers that just want a
# name in their locale now get one, so `localized[locale] ?? display_name` is the
# whole of it — `?? latin` remains only as the last cell for a name with nothing
# on file in that locale, and it is now rarely reached.
#
# Contract prose: docs/catalog/01-service-and-contract.md §1 (last two paragraphs)
# and docs/developer-platform/02-public-api.md §3.7.

# Wave 212 wave B (2026-08-19) deletes the d7 four-slot compat layer. Wave A
# had every work projection dual-emit the legacy
# `names{ja-jp, zh-cn, zh-tw, en-us}` block AND the wave-209 name primitive
# `latin` + `localized{}`; this wave removes the first half. Both consumers —
# the kungal forum and moyu/patch — have migrated to `localized{}` and deployed,
# and the forum decodes work intros in either shape, so the transition window is
# closed. Completion criterion: no `ja-jp` / `zh-cn` / `zh-tw` / `en-us` key
# appears anywhere on the public face or in this spec.
#
# Three removals, of which only the last two are ERR-visible:
#
# (1) the `names` block itself, on every projection that carried it (works list
# and search rows, work briefs, relations, series siblings, calendar rows,
# entity-search work hits). oasdiff reports these as WARNINGs, not errors — the
# block was optional everywhere — so they take no entry below. The replacement
# shipped in wave A: `localized[locale] ?? display_name ?? latin`, the render
# rule every other name on this face already follows. The four slots were lossy
# by construction: a ko/ru/vi or untagged title had no slot to go to.
#
# (2) the works-list `intros` block changes shape from the four fixed slots to
# `[{lang, intro, source, machine}]` — the generic PublicIntro array the work
# DETAIL face has published since wave 209, one element per language, elected
# out of the same rows by the same first-row-wins scan. List and detail now
# answer with identical arrays for the same work. That is the
# `object` → `array<object>, null` change below; `null` is the include-gated
# absence (no `include=intros`, no block), which is what the absent object
# meant too.
#
# (3) the work-detail synopsis key `intro` is renamed to `intros`, matching the
# list block and the label/tag/character/name faces. Same array, same elements,
# same order — only the key moved. The S2S read face keeps its own `intro`; it
# is a different face and is untouched by this wave.
#
# Also dropped, and warning-only for the same optionality reason: the flat trait
# keys `name_zh` / `group_zh`, superseded in wave A by
# `traits[].localized["zh-Hans"]` and `group_localized["zh-Hans"]`, which carry
# the same strings plus their provenance.
#
# NOT changed, deliberately: the `include=` token spellings. `include=names`
# still gates `latin` + `localized{}` on the list faces, `include=intros` still
# gates the intro block. moyu renders every work title through `include=names`;
# renaming that token would empty its titles site-wide and raise nothing on
# either side, so the tokens outlive the block they were named for.
